# Security reporting

Do not publish vulnerabilities, credentials, session tokens, or private records in public issues. Once the repository is hosted on GitHub, use its Security tab to report a vulnerability privately if private reporting is enabled. Otherwise contact the repository owner through an established private channel. A dedicated contact and response policy have not yet been configured.

Include the affected commit, reproduction steps with synthetic data, impact, and sanitized evidence. Do not test against systems you do not own or have permission to assess.

This project is a local defensive workspace with demonstration workflows. No independently audited production release or supported-version policy has been established. See the [gap assessment](full-product/docs/GAPS.md).
